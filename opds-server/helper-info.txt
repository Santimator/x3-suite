opds-server.service — what the commands do
==========================================

First, edit opds-server.service: replace both CHANGEMEs with the account whose
home holds the books, and the path where you cloned the repo.


INSTALLING
----------

  sudo cp opds-server/opds-server.service /etc/systemd/system/

      A plain file copy. /etc/systemd/system/ is where systemd looks for units,
      and it's the directory for yours specifically — /usr/lib/systemd/system/
      belongs to packages. Nothing runs yet; systemd hasn't looked.

  sudo systemctl daemon-reload

      Tells systemd to re-read unit files from disk. The step everyone forgets:
      without it you get "unit not found" for a new file, or systemd keeps
      quietly running the old version of one you edited.

  sudo systemctl enable --now opds-server

      Two things. "enable" wires it into boot — it reads WantedBy=multi-user.target
      from the unit's [Install] section and creates a symlink. "--now" also starts
      it immediately, so you don't reboot to find out whether it works.

  journalctl -u opds-server -f

      systemd captures the script's output into the journal; this reads it back,
      filtered to this unit, following live like tail -f. You'll see the startup
      banner — book count, config source, and the URL to type into the reader —
      then a line per request.

      Ctrl-C stops watching the log. It does not stop the service.


DAY TO DAY
----------

  systemctl status opds-server              is it up, and the last few log lines
  sudo systemctl restart opds-server        after editing config.json
  sudo systemctl stop opds-server           stop now, still starts at boot
  sudo systemctl disable --now opds-server  stop now and unhook it from boot
  journalctl -u opds-server -n 50           last 50 lines, without following
  journalctl -u opds-server --since today   just today's


SETTINGS
--------

The unit runs the script with no flags, so everything comes from defaults or
from config.json — nothing here duplicates them, and changing the port is a
restart and nothing else.

With no config.json at all: serves workspace/ on 0.0.0.0:6737, open, 25 entries
per page. The banner prints "config (defaults)" when that's what you're on.

To change something permanently, copy config.example.json to config.json (it's
gitignored, every key annotated) and restart. Basic auth lives there too:
auth.username, plus the password in secrets/ — see secrets/README.md.


IF THE READER SAYS "Failed to fetch feed"
-----------------------------------------

Check the log first; it tells the cases apart:

  "TLS handshake on a plain-HTTP port"   the URL saved on the device starts with
                                         https:// — re-enter it with http://

  nothing at all                         the request never arrived: wrong IP,
                                         different network, or a firewall

  401                                    auth is on and the device isn't sending
                                         usable credentials

  200, but the device says "No entries"  the feed arrived and parsed; run
                                         scripts/selftest.py

SKILL.md has the longer version of all of this.
