tgbot.service — what the commands do
====================================

First, edit tgbot.service: replace every CHANGEME with the account that owns
the repo, and the path where you cloned it. There are five, and they must all
match — three of them are ReadWritePaths, which is what stops the bot from
being confined out of its own workspace.

Before any of this, the bot needs two things it will not start without: your
numeric Telegram id and the bot token. By default those live in
tgbot/config.json and tgbot/secrets/telegram.token. If coding agents have read
access to this checkout, set "secrets_dir" in config.json to a directory
outside it and keep both there instead — see secrets/README.md.

If you moved them, add the same path to ReadWritePaths only if the bot needs to
write there. It does not: it only reads those two files, so no change is needed
to the unit.


INSTALLING
----------

  sudo cp tgbot/tgbot.service /etc/systemd/system/

      A plain file copy. /etc/systemd/system/ is where systemd looks for units,
      and it's the directory for yours specifically — /usr/lib/systemd/system/
      belongs to packages. Nothing runs yet; systemd hasn't looked.

  sudo systemctl daemon-reload

      Tells systemd to re-read unit files from disk. The step everyone forgets:
      without it you get "unit not found" for a new file, or systemd keeps
      quietly running the old version of one you edited.

  sudo systemctl enable --now tgbot

      "enable" wires it into boot; "--now" also starts it immediately, so you
      don't reboot to find out whether it works.

  sudo journalctl -u tgbot -f

      The bot logs here: what it received, what it ignored, what failed. On a
      good start you'll see the bot's @username and the user id it is serving,
      and your phone will get a "Let's read!" with the menu.

      The sudo matters. A system unit logs to the system journal even when it
      runs as you, and without root you see only your own journal. To drop it
      permanently:

          sudo usermod -aG adm $USER      # log out and back in

      Ctrl-C stops watching the log. It does not stop the service.


DAY TO DAY
----------

  systemctl status tgbot                is it up, and the last few log lines
  sudo systemctl restart tgbot          after editing config.json
  sudo systemctl stop tgbot             stop now, still starts at boot
  sudo systemctl disable --now tgbot    stop now and unhook it from boot
  sudo journalctl -u tgbot -n 50        last 50 lines, without following
  sudo journalctl -u tgbot --since today   just today's


WHEN SOMETHING IS WRONG
-----------------------

  It never answers, and the log says
  "ignored update from user=NNN"

      That NNN is you. Put it in config.json as telegram.user_id and restart.
      This is the single most common setup mistake, and the log line exists so
      it takes ten seconds instead of an evening.

  It won't start: "no bot token"

      tgbot/secrets/telegram.token is missing or empty. See secrets/README.md.

  It won't start: "no telegram.user_id"

      There is no config.json, or it doesn't have one. Copy
      config.example.json to config.json.

  A photo arrives and nothing happens; the log shows a Pillow ImportError

      The wallpaper converter needs Pillow, which lives in the repo venv:

          python3 -m venv .venv
          .venv/bin/pip install -r wallpaper-maker/requirements.txt

      The bot finds .venv/bin/python by itself once it exists. The bot's own
      code needs nothing installed — only the converter does.

  Read-only file system errors in the log

      A CHANGEME in one of the three ReadWritePaths lines doesn't match where
      the repo actually is. They are absolute paths and must be exact.

  "📵 No reader found" every time

      The X3 only runs its web server while it is on Home → File Transfer →
      Join a Network, and it stops the moment you leave that screen. Nothing
      is lost — the queue is untouched when a push fails.


WHAT IT DOES TO YOUR FILES
--------------------------

Writes: workspace/ (wallpapers, staged PDFs, books), tgbot/state/ (the queue),
and wallpaper-maker/last-device.json (the reader's address, remembered).

Deletes: only inside workspace/, only on a second confirming tap.

On the device: only what you ask for, only while you are pushing or browsing.

SKILL.md has the longer version of all of this.
